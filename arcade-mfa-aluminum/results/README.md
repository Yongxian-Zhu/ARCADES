# Results

Published outputs for the two reconciliations and the analyses supporting them.
Everything here is regenerated by the commands in the top-level README; nothing
is hand-edited.

## `aluminum_2017_baseline/`, `aluminum_2022_update/`

The two headline runs, complete with posterior draws.

| File | Contents |
|---|---|
| `posterior_mean.csv` | one row per flow: node pair, posterior mean |
| `posterior_samples.npy` | `(n_draws, n_flows)` posterior draws; every credible interval in the paper comes from these |
| `convergence_summary.csv` | per-flow split-R-hat, effective sample size, quantiles, converged flag |
| `node_balance_diagnostics.csv` | per-node mass-balance residual in kt/y and as a percentage of node throughput, with credible intervals |
| `source_inventory.csv` | every observation entering the likelihood, with source, pedigree scores and derived sigma |
| `attribution.csv` | per-flow precision shares: how much of each flow is set by observation, prior, mass balance or allocation structure |
| `allocation_residuals.csv` | realized deviation from each transferred allocation share (2022 only) |
| `aggregate_observations.csv` | reported totals against reconciled sums (2022 only) |
| `plots/` | credible-interval Sankey diagrams, absolute and relative |

## `si_tables/`

Supporting Information tables, assembled from the run directories by
`scripts/build_si_tables.py`. One set per run plus `run_summary.csv`, which
carries the convergence and mass-balance headline numbers for both years.

## `robustness/`

One directory per case from `scripts/run_robustness_suite.py`, plus
`comparison.csv` -- the cross-case table. Each row is one set of modelling
assumptions and the resulting headline indicators with credible intervals, so a
conclusion can be checked for dependence on any single assumption.

Read the `exercised` column first. A case that reproduces the baseline exactly
varies an assumption that has no effect on this configuration -- the pedigree
mapping does nothing in a year whose observations carry no pedigree scores, for
instance. Those rows are marked `False` and are UNTESTED, not robust.

Posterior draws are omitted here to keep the repository small; re-run the suite
from the shipped configuration to regenerate them.

## `aluminum_2017_node_allocation/`, `aluminum_2022_node_allocation/`

The same two reconciliations under the node-allocation formulation, where node
throughputs and Dirichlet allocation shares are the variables instead of the
flows. `posterior_mean.csv` uses the same schema as the flow runs, so the Sankey
script works against these directories unchanged.

`node_summary.csv` gives, per source node, how much of it was observed, the
quality index, the Dirichlet concentration and the fitted throughput;
`allocation_shares_map.csv` gives the fitted and observed split per flow.

There is deliberately no `convergence_summary.csv`: the Laplace sampler returns
independent draws, so split-Rhat and ESS would be 1.0 and the draw count by
construction -- a clean bill of health that measured nothing.

## `pedigree_sensitivity/`

Sweep over the pedigree-to-sigma mapping from
`scripts/run_pedigree_sensitivity.py`, run against 2017 -- the year whose
observations carry pedigree scores.

`indicators.csv` gives the aggregate indicators, the median relative
credible-interval width and the worst node residual for every mapping case;
`comparison.csv` gives the per-case flow-level view. The mapping barely moves
the reconciled values but is the dominant control on reported interval width,
so read any precision claim against this table.

## `holdout_aluminum_2017/`, `holdout_aluminum_2022/`

Leave-one-source-out validation from `scripts/run_holdout_validation.py`.

`holdout_summary.csv` scores each withheld source on 95% interval coverage,
percentage error and error in units of the withheld value's own sigma;
`holdout_detail.csv` gives the per-observation predictions behind it.

Read the `diagnostic` column first. A source supplying most of the evidence
cannot be withheld and then predicted -- the model has nothing left to predict
from -- so those rows are flagged `False` and measure dependence on that source
rather than predictive accuracy.
